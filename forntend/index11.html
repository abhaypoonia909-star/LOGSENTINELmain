College demonstration

Guided walkthrough

Optional first-time path using the labeled sample log and the isolated demo-login page. Regular uploads and analysis still work without this section.

Demonstration data is synthetic. The built-in sample and samples/multi_attack_demo.log are for evaluation only. Live alerts are never seeded automatically.
STEP 01

Load the sample log

Open Log Analyzer and click Load Sample Log. The filename is labeled as demonstration data.

STEP 02

Run analysis

Click Run Analysis. Wait for the Attack Summary table: one row per distinct attack type, with real attempt counts and source IPs.

STEP 03

Download the PDF

Use Download PDF Report. The report matches the Attack Summary table and does not invent missing IPs.

STEP 04

Test demo-login alerts

Open the isolated demo login. Five failed passwords from one IP create a HIGH brute-force alert. Then open Live Alerts.

STEP 05

Ask SentinelAI

Open the assistant and ask a question such as “What attacks were detected?” It uses local Ollama and attaches analysis only when relevant.

Platform Capabilities

What this platform does

LogSentinel combines a log parser, rule-based detectors, visual analytics, a local assistant, and a source-code scanner. Metrics come from your uploads and stored alerts — not invented examples.

🔍
Auto Format Detection
Regex probing identifies syslog, Apache, or Nginx access logs before selecting the optimal parser — no configuration needed.
🛡
Rule-Based Threat Engine
Detects brute-force login attempts, port scans, directory traversal, SQL injection indicators, and critical system failures using heuristic rules.
📊
Visual Analytics Dashboard
Real-time charts, risk rings, IP heatmaps, severity distribution, and threat timelines rendered directly from your log data.
⚡
Pandas-Powered Analysis
Pandas DataFrame operations parse and analyze uploaded logs locally. Throughput depends on the file and the machine running Flask.
🧩
Modular Architecture
Each stage — parsing, analysis, charting, reporting — is an independent module that's easy to extend, test, or plug into existing pipelines.
🎯
Heuristic Risk Score
A 0–100 composite score derived from brute-force sources, intrusion events, critical alerts, and error volume. Instant threat severity at a glance.
🚨
Real-Time Security Alerts
Live failed-login and injection-pattern alerts from the isolated demo-login page, with filtering, persistence, and optional demo-only IP mitigation.
Threat Detection

Four-Layer Detection Engine

Each layer targets a distinct attack vector with tuned pattern-matching rules and configurable thresholds.

🔐
Brute-Force Login Detection
Counts failed authentication attempts per IP. IPs exceeding the threshold (default: 5) are flagged with attempt counts and severity classification.
CRITICAL LAYER
📡
Port Scan Detection
Identifies rapid sequential connection attempts across multiple ports from a single source, a classic reconnaissance signature.
HIGH PRIORITY
💉
Intrusion Pattern Analysis
Detects directory traversal (../), SQL injection fragments, shell access patterns, and common web exploit signatures in URL paths and messages.
PATTERN MATCH
⚠
Critical Event Monitor
Surfaces justified critical-system matches such as kernel panic, OOM killer, and segfault. Privilege-escalation evidence stays on the intrusion finding.

Vulnerability Scanner

Local SAST for individual files or ZIP projects. Supported when rules exist and are tested: .py, .js/.jsx/.ts/.tsx, .php, .html, .css, .java, .cs, .sql, config (.json/.yml/.env), and .txt. A .txt file can be source code or security logs — choose below. Findings are pattern matches, not a guarantee the project is secure.

Choose a source file, text file, or project ZIP, then run the scanner.

Code-scan upload limit: 50 MB compressed (CODE_SCAN_MAX_UPLOAD_BYTES). Log analysis remains 10 MB. ZIP members are read in memory, never extracted to arbitrary paths. Nested ZIP files, vendor folders, path traversal, and ZIP-bomb ratios are skipped with reasons. If a limit stops the scan, the summary says so.
